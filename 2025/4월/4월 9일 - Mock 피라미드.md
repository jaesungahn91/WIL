피라미드의 위로 갈수록 목 비용은 높아짐. 고수준 목에는 다음과 같은 특징이 있다.
- 작성에 많은 시간이 소요된다.
- 초기화 작업을 위한 비용이 크다.
- 변경된 목의 상태를 추적하기 어렵다.
따라서 고수준 목을 많이 사용할수록 테스트를 작성하기 어려워진다.
### 1. Network mock
네트워크 통신 대상을 대체하는 목. 테스트를 위해 별도의 목 서버나 DB를 실행하는 경우. 일반적으로 프록시를 사용해 테스트 서버에 연결하거나, 테스트용 DB의 데이터를 지정된 값으로 초기화하는 방식을 사용.

네트워크 목을 사용하면 목을 구현하거나 데이터를 변경하기 위해 테스트 외부에 있는 별도 코드를 수정해야 한다. 이 과정이 불편한 것은 둘째 치고 의도하지 않은 테스트 케이스가 깨지는 경우도 빈번히 발생한다.

### 2. Global mock
전역 객체를 대체하는 목.

### 3. Object spying
클래스의 일부 메서드를 스파이 함수로 감싸는 작업. 글로벌 객체를 스파잉하는 경우에는 글로벌 모킹과 같이 초기화 및 복원 작업을 필요로 한다.

### 4. Dummy, Stub
테스트용 가짜 객체 혹은 임시 데이터. 목 피라미드의 가장 아래 계층에 있으며 작성과 변경이 쉽다. 또한 각 테스트 케이스에 대응하는 데이터를 필요할 때 선언할 수 있으므로 테스트마다 독립적으로 존재하여 복원 작업이 필요하지 않다.
